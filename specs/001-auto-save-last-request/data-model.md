# 数据模型：自动保存最近一次请求记录

## 调试上下文

代表一条历史记录所属的范围，用于匹配和隔离最近一次记录。

**字段**：

- `projectPath`：归属项目路径，需使用项目现有规范化路径策略。
- `baseUrl`：发送请求时选中的 Base URL，例如 `https://localhost:5001`。
- `method`：HTTP 方法，统一使用大写形式。
- `routeTemplate`：接口路由模板，保留路由占位符语义。
- `action`：接口 Action 名称，可用于进一步区分同路由场景。

**校验规则**：

- `projectPath`、`baseUrl`、`method`、`routeTemplate` 是隔离历史记录的核心字段。
- `baseUrl` 为空时只能匹配空 Base URL 的记录，不能回退匹配其他 Base URL。
- 上下文键必须稳定，避免 Query 或 Body 值变化导致同一接口记录无法覆盖。
- 恢复历史时不得用旧上下文覆盖当前面板已初始化出的接口元信息。

## 测试请求输入记录

代表用户最近一次发送时可复测的请求输入，范围对应规格中的 Auth、Headers、Query、Body。

**字段**：

- `id`：历史记录唯一标识。
- `timestamp`：保存时间，毫秒时间戳。
- `context`：调试上下文。
- `auth`：当前支持的认证输入；Bearer Token 仅在用户配置允许保存时可恢复。
- `headers`：用户发送时配置的请求头集合，敏感信息按产品策略保存或剔除。
- `query`：用户发送时保留在 Query 中的参数字符串，敏感键按现有规则脱敏。
- `bodyMode`：`json`、`formdata` 或 `binary`。
- `body`：JSON 或文本 Body，按大小限制保存。
- `formDataFields`：FormData 字段列表；文本字段可保存，文件字段保存文件名、类型和在大小限制内的内容。
- `binaryBodyBase64`：Binary 模式文件内容；仅在大小限制内保存。
- `binaryContentType`：Binary 文件类型。
- `binaryFileName`：Binary 文件名。

**校验规则**：

- 写入前必须执行现有敏感信息处理。
- 超出保存限制的内容不得写入完整值，应保存空值、摘要或元数据。
- 恢复到 WebView 后所有请求输入必须可编辑。
- 用户编辑恢复出的内容不改变已保存记录，只有再次发送后才替换最近一次记录。

## 响应结果记录

代表最近一次请求的可展示结果。

**字段**：

- `success`：请求是否获得成功响应。
- `statusCode`：HTTP 状态码；发送失败时可为空。
- `headers`：响应头集合。
- `body`：响应体文本；超限时保存降级内容或空值。
- `duration`：请求耗时毫秒。
- `error`：发送失败或网络错误信息。
- `errorCode`：网络错误码或分类码。

**校验规则**：

- 恢复响应结果不得触发新的网络请求。
- 成功响应和失败响应都必须能被 WebView 识别并渲染。
- 响应体超限时，恢复界面应能显示可理解的空状态或摘要。

## 状态流转

```text
无历史记录
  -> 用户发送请求
  -> 保存调试上下文、测试请求输入记录和响应结果记录
  -> 最近一次记录可恢复
  -> 用户重新打开同一上下文测试面板
  -> WebView 自动应用最近一次记录
  -> 用户编辑但未发送
  -> 最近一次记录保持不变
  -> 用户再次发送
  -> 最近一次记录被新记录替换
```
