# 快速验证：自动保存最近一次请求记录

## 前置条件

- 已安装依赖：`npm install`
- VS Code 可启动本扩展的 Extension Host
- 工作区中存在可被 CodeLens 识别的 C# Web API 项目
- `csharpApiConsole.requestHistoryEnabled` 保持启用

## 构建检查

```powershell
npm run compile
```

预期结果：TypeScript 编译通过，没有新增类型错误。

## 场景 1：重新打开同一接口自动恢复

1. 在 C# 控制器中点击某个接口的测试入口，打开测试面板。
2. 填写或修改 Auth、Headers、Query、Body。
3. 点击 Send，等待响应显示完成。
4. 关闭该测试面板。
5. 再次通过同一接口打开测试面板。

预期结果：

- 面板在 3 秒内自动恢复最近一次 Auth、Headers、Query、Body。
- 响应区域显示最近一次响应状态、响应头、响应内容、耗时或错误信息。
- 响应区域明确标识该结果来自最近一次已发送请求，不是打开面板时产生的新响应。
- 不会在打开面板时自动重新发送请求。
- 不需要手动选择历史下拉即可直接再次发送。

## 场景 2：连续发送只恢复最后一次

1. 对同一接口连续发送 5 次请求，每次使用不同 Auth、Headers、Query 或 Body。
2. 关闭并重新打开该接口测试面板。

预期结果：

- 恢复第 5 次发送的请求输入和响应结果。
- 历史下拉仍可选择较早记录。

## 场景 3：不同 Base URL 不串用

1. 在同一接口下选择 Base URL A，发送请求。
2. 切换到 Base URL B，发送不同请求。
3. 关闭并重新打开面板，分别选择 Base URL A 和 Base URL B。

预期结果：

- Base URL A 只恢复 A 的最近请求输入和响应结果。
- Base URL B 只恢复 B 的最近请求输入和响应结果。
- 两个环境的 Auth、Headers、Query、Body 和响应结果不会互相覆盖。

## 场景 4：无历史记录保持默认体验

1. 打开一个从未发送过请求的接口。

预期结果：

- 不显示其他接口的历史请求或响应。
- 现有自动 Query 参数、Body 模式推荐等默认预填行为保持不变。

## 场景 5：损坏历史记录回退默认体验

1. 准备一个包含损坏历史记录的工作区状态，例如历史项缺少必要字段、字段类型异常或响应快照不可解析。
2. 打开该历史记录对应的接口测试面板。

预期结果：

- 面板不会崩溃或卡住。
- 不应用损坏历史记录中的请求输入或响应结果。
- 面板回退到无历史记录时的默认打开体验。

## 场景 6：敏感信息和大内容

1. 关闭 `requestHistorySaveBearerToken` 后发送包含 Bearer Token 的请求。
2. 重新打开面板。
3. 发送超出 `requestHistoryMaxBodyKb` 限制的请求体或响应体。
4. 重新打开面板。

预期结果：

- Bearer Token 不会通过历史记录恢复。
- 超限内容不会完整保存；面板仍可恢复可用部分并保持可编辑。
